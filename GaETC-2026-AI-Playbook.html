Obsidian + Claude: How They Fit

The System

Obsidian — the knowledge layer

  • Local Markdown files on your computer
  • Organized vault of notes, summaries, references
  • Nothing goes to the cloud unless you choose

Claude — the AI layer

  • Connected directly to your vault via the desktop app
  • Reads your notes and context files — no pasting required
  • Outputs land back in the vault, ready for next time

Closing the Loop — The End-of-Day Routine

Feeding the Machine

I type one word: EOD

  1. Session log — Claude writes a dated summary of the day's work into the vault.
  2. Loose ends — it lists the action items and dates that came up, and I confirm which are real.
  3. Calendar handoff — confirmed items come out as copy-paste blocks for my work calendar tool.
  4. Context refresh — if anything standing changed, it updates the context file.
Tomorrow's session starts where today's ended.
Calendar handoff block (example)
Please process the following calendar actions: --- ### CALENDAR EVENTS **Event 1:** * **Title:** ARIC Fall Retreat - Day 2 * **Date:** 2026-10-21 * **Time:** 9:00 AM to 4:00 PM --- ### TASKS **Task 1:** * **Title:** Review Needs Assessment responses * **Due Date:** 2026-11-20
Lesson learned: one task per paste — calendar assistants mix up bundled items.

Publishing

GitHub Pages. No web team, no CMS, no hosting bill.

4 MIN

One File. One Upload. Public URL.

Publishing

The workflow

  • Claude builds the HTML file
  • Upload to a GitHub repository
  • GitHub Pages publishes it instantly
  • Add a short link (Rebrandly, bit.ly) for sharing

What you get

  • A permanent, shareable URL
  • Free hosting, no maintenance
  • Update the file → URL stays the same
Lesson learned
Some school networks block bit.ly or GitHub. Keep a PDF copy of each page in a shared Drive folder and link it from your index page.

06

Privacy & Trust by Design

FERPA compliance isn't a disclaimer at the end. It's a design principle from the start. So is checking the AI's work.

6 MIN

What Goes In — What Never Does

Privacy & Trust
✓
Claude can see this
→ Meeting notes & agendas
→ Publicly available information
→ Your own professional documents
→ Formatting & document creation tasks
→ Research & reference work
FERPA Line
✕
Never goes to Claude
→ Student names, IDs, grades, or records
→ Staff evaluations or personnel files
→ Anything under FERPA, HIPAA, or a confidentiality obligation
→ Internal legal or HR communications

The workflow is designed around this line — not as an afterthought, but as the first decision.

Note: Because the vault is what Claude has access to, keeping data out of Claude means keeping it out of the vault. Options include mounting only a subfolder or maintaining a separate vault for protected data — ask your AI platform what works best for your situation.

Trust, but Verify

Privacy & Trust
Check the facts

AI writes confident prose, including confident mistakes.

Real example: I asked an AI tool to explain the legal basis for a set of state program standards. Checked against the state code, the administrative code, and the standards document itself, it had invented some citations and misattributed others.

AI drafts. Primary sources decide.
Check accessibility (Section 508)

AI is a good accessibility collaborator, if you ask. Have it review every page for:

  • Color contrast
  • Alt text on every image
  • Heading order and semantic HTML
  • Descriptive link text and keyboard use
"Review this page for Section 508 / WCAG issues: contrast, alt text, heading order, link text, keyboard use. List the problems, then fix them."

Then test it yourself with a screen reader before calling it done.

Here's a workflow I saw demonstrated today:

Obsidian (free, local note-taking app) serves as a personal knowledge vault — meeting notes, email summaries, role context, and reference documents. An AI assistant (Claude, ChatGPT, Gemini) with access to that vault drafts documents, builds public-facing resources, and carries context forward across sessions — no more starting from zero each time. Outputs are built as single HTML files, published to GitHub Pages, and shared via short links — no web team, no CMS, no cost.

As the vault grows, the workflow grows with it. The documents you can build and publish will change as your knowledge base does — what starts as a simple reference page can evolve into something more connected and complex over time.
